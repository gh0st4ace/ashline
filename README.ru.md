## Быстрый старт

### 1. Требования

Windows 10/11, PowerShell 5.1+, рабочая установка OpenCode. Остальное
проверяет установщик и говорит, чего не хватает, вместо того чтобы молча
упасть.

### 2. Посмотреть план

```powershell
.\install.ps1 -DryRun
```

Каждый шаг печатается до выполнения. Ничего не пишется, пока не убрать флаг.

### 3. Установить

```powershell
.\install.ps1                 # только конфигурация, в ~/.config/opencode
.\install.ps1 -Profile full   # + тулчейны, коллекции, MCP-серверы
```

### 4. Доказать, что установка удалась

```powershell
.\scripts\verify-setup.ps1     # проверка всего стека, всегда код 0
py -3 .\scripts\doctor.py      # здоровье рантайма, коды 0 / 1 / 2
```

`verify-setup.ps1` и `doctor.py` не дублируют друг друга. Первый проверяет
**тулчейн и обвязку**, второй — **работающую установку**. Подробности в
[docs/scripts.md](docs/scripts.md#два-проверяющих-инструмента).

### 5. Спросить

```text
/verify    проверить здоровье всего стека
/stack     состояние скилов, коллекций, движков, памяти на одном экране
/refresh   обновить все коллекции и перелинковать скилы
/re        реверс-инжиниринг бинарника через REA
```

## Почему так устроено

Четыре решения держат остальное. Каждое принято против отказа, а не по вкусу,
и каждое обратимо, если вы не согласны.

### 1. Метки доказательности обязательны

Каждое утверждение — **verified**, **reported** или **inferred**. Наличие
проекта в коллекции не доказывает способность. «Сводка утверждает» и «исходный
код показывает» — разные факты, и записываются они по-разному.

Это закреплено структурно: evidence-листы в `kernel-sec` не принимают утверждение
без *источника, даты, затронутых версий, уверенности и фальсификатора* — то
есть наблюдения, которое его опровергло. [Фальсификатор работающий, а не
декоративный](docs/knowledge-workspaces.md#конвенция-фальсификатора): найденный
на диске `dbutil_2_3.sys` — **не** доказательство CVE-2021-21551, и лист
прямо говорит, какая проверка это решает.

### 2. Приборы приборятся сами

Самый дорогой урок этого окружения: **уверенный инструмент дал неверный ответ,
и неверному ответу поверили.** Список модулей прочитан по неверному смещению и
принят с числом, которое не помещалось в буфер. Декомпилятор, отрендеривший
драйвер как `return;`, был использован для вывода, который этим отличить
невозможно.

Поэтому `verify-setup.ps1` **запускает** каждый инструмент и печатает его баннер
вместо разрешения пути, отвергает `Traceback (most recent call last):` как
успешный баннер и ограничивает каждую подстроку. Инструмент, который
разрешился в `PATH`, не доказывает ничего.

### 3. Коллекции — зависимости, а не вендоринг

21,2 ГиБ в семи коллекциях. Они клонируются, пинятся и перелинковываются
скриптом. Вендоринг означал бы перепубликацию чужой MIT-работы, сломался бы
при каждом движении вверх по течению и сделал бы репозиторий непригодным.

### 4. Тесты ядра — только в VM со снапшотами

Это не ограничение области, а дисциплина отката. Кривой `.sys` уводит машину
в BSOD. `vmhelper.ps1` даёт `snap` / `rollback`, и каждый тест драйвера идёт
внутри `ac-test` — одноразовой Windows 10 LTSC VM на VirtualBox.

## Инструменты

### Проверки

| Прибор | Что отвечает | Код возврата |
| --- | --- | --- |
| `verify-setup.ps1` | Цел ли тулчейн и обвязка? | всегда `0` |
| `doctor.py` | Здорова ли работающая установка OpenCode? | `0` / `1` / `2` |
| `maintain.ps1` | Что можно вернуть, что устарело? | `0` |
| `selfcheck.ps1` (в каждой базе) | Согласована ли база знаний? | `0` / `1` |

`doctor.py` — единственный, пригодный как CI-гейт: единственный, кто возвращает
ненулевой код. Он ловит отказы, которые здесь действительно останавливали работу:
рассинхрон версий движков, призрачные сессии, раздутый кэш плагинов, сессии
свыше 400 сообщений с нулём *завершённых* сжатий, и **дрейф идентичности
клиента** — несовпадение PE `TimeDateStamp`, обесценивающее молча все смещения,
выведенные вчера.

### Движки анализа

| Задача | Инструмент | Примечания |
| --- | --- | --- |
| Нативная декомпиляция | **Ghidra 12.1.4** headless | Провайдер по умолчанию, без GUI, без ручного шага |
| Второе мнение | **IDA Pro 9.4** attached | `start-ida-mcp.ps1` открывает бинарь и поднимает мост |
| Отладка ядра | **WinDbg** | user mode через x64dbg, kernel mode через `windbg`/`cdb`/`kd` |
| Что умеет этот бинарь | **capa 9.4.0** | Карта возможностей с ATT&CK ID — гонять первым на незнакомом |
| Какие строки спрятаны | **FLOSS 3.1.1** | Собираемые со стека, base64, обфусцированные |
| Что его защищает | **DIE 3.10** | Идентификация протектора/упаковщика |
| Строки и импорты | **radare2 6.2.4** | `r2`, `rabin2`, `radiff2` |

> [!NOTE]
> Передавайте REA **адрес**, а не голое имя функции. Голое имя резолвится у
> некоторых инструментов и падает у других с `unreadable_output`. Сначала
> `list_procedures`, чтобы узнать адресное пространство.

### Не установлено, и почему

| Инструмент | Причина |
| --- | --- |
| John the Ripper | Openwall публикует только Unix-исходники; официальной Windows-сборки нет. `hashcat` закрывает задачу. Сторонние зеркала не используем. |
| metasploit, burpsuite, zap | GUI-установщики на сотни мегабайт, низкий возврат против этого каталога. |
| frida-server | Полезен только против реального Android-устройства; устройство не подключено. |
| pentestMCP | Требует Docker, которого нет. |
