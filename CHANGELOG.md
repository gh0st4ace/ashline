### The toolchain, and why it is not 25 GB

Asked whether the capture was complete. It was not: **the toolchain had been
left out entirely.** Measured on disk:

    D:\opencode   22.36 GiB   21.24 GiB of it other people's repos
    D:\Tools       8.32 GiB   the tools (4.67 GiB of it VM media)
    ashline        0.95 MiB   what ships

So the binaries are not vendored, and cannot be: GitHub's per-file limit is
100 MB against Ghidra at 865 MiB, hashcat 371, Sysinternals 272, JDK 328, dnSpy
203; IDA Pro and the Windows SDK are commercial or EULA; and repackaging a
vendor's build is not sharing.

What was missing is the **contract**, and that is now present:

- `config/tool-manifest.json` - generated by `tools/gen-tool-manifest.py`, a
  scan of the disk. 32 tools, each with size, role, source URL, license,
  installer script, and the skills that depend on it. Nothing hand-maintained,
  nothing invented: absent tools are reported absent, not assumed.
- `docs/tools.md` - the human table, plus why nothing is vendored, plus the
  portable-export path.
- `docs/working-shell.md` - the whole environment on one page: 32 tools, 174
  skills, 109 commands, 7 collections, 6 MCP servers, 277 tools, 4 agents,
  21 scripts, 2 knowledge workspaces.
- `scripts/install-all-tools.ps1` - orchestrates the six installers **in the
  order that matters**. Passes 1-3 are one measured gap list, and pass 3 repairs
  four named bugs pass 2 shipped (httpx matched by filename into an unrelated
  Python client; invalid `latest/download` URLs writing 404 pages to disk;
  Sysinternals extracted with zero shims; impacket `.py` entry points).
- `scripts/export-portable-bundle.ps1` - the other channel. Packs the toolchain
  into a zip for offline transport, with `triage` / `re` / `game` / `all`
  profiles. Excludes non-redistributable tooling unless `-IncludeUnsafe`, and
  says so in a README written next to the archive.

Two runtime bugs found and fixed while building these:

- `PROFILES` and `UNSAFE` were missing their `$` sigil. They **parsed cleanly**
  and failed only on the code path that touched them, which is why a parse-only
  gate waved them through.
- The gate is now `gate_powershell_runtime`, which executes every
  preview-capable script under `-DryRun` and fails on
  `CommandNotFoundException`. A script that parses and then dies at runtime is
  a real failure mode that parsing cannot see.

**Encoding bug found and fixed on the completeness pass**

`scripts/update-ecc.ps1` and both `selfcheck.ps1` files contain Russian text,
and Windows PowerShell 5.1 decides a script's encoding from its BOM: no BOM
means ANSI, so non-ASCII becomes mojibake. That is cosmetic — until a mangled
byte lands on `"` and terminates a string literal early, which turned
`update-ecc.ps1` into a parse error. Fixed by writing those three files as
UTF-8 **with** BOM.

The gate that caught this asserted "all `.ps1` must be ASCII", which was itself
wrong: a non-ASCII script carrying a BOM is correct. The rule is now:

| Content | Encoding |
| --- | --- |
| Non-ASCII present | UTF-8 **with** BOM — required |
| Pure ASCII | no BOM — a BOM breaks YAML frontmatter |

`tools/fix-ps1-encoding.py` applies it.

### Excluded, deliberately

Recorded here so the omissions are visible rather than looking like oversights:

- **21.2 GiB of third-party collections.** Declared as pinned dependencies.
  Vendoring would republish other people's MIT work, break on every upstream
  commit, and exceed GitHub's 100 MB per-file limit.
- **ECC's 315 skills, 103 commands, 9 tools, hooks, plugins.** Installed via
  ECC's own installer; declared as a dependency with its commit pinned.
- **LLM-jailbreak prompt agents.** Not methodology.
- **Operator-local scope-override directives.** An instruction to the assistant,
  not a reusable practice, and not something a public repository should carry.
- **A live-format password** that existed in the source config's `service.json`.
  Never copied; the sanitizer asserts its absence.
- **Separate private projects** (a DayZ kernel-driver project and others) that
  live in their own repositories.

### Known limitations

- `verify-setup.ps1` prints a green `OK` for several checks that describe a
  failure state, including a dropped junction (`'0/12'`). Documented in
  `docs/troubleshooting.md#false-green-in-verify-setup` rather than hidden.
- `doctor.py` liveness-probes a process with `os.kill(pid, 0)`, which on Windows
  may terminate the process rather than probe it. Flagged in
  `docs/scripts.md`; not confirmed on this host.
- `install-missing-tools2.ps1` derives its scripts directory from
  `sysconfig`, while passes 3 and the triage installer hardcode an absolute
  Python path. A Python version change would silently drop the floss and
  impacket shims.
- Junction counts in `verify-setup.ps1` are hardcoded at 12/93/3 and do not
  compare against disk. Correct today, not self-updating.
- `sync-awgs-skills.ps1` calls `git -C $Repo pull` without
  `-c safe.directory=`, unlike every other updater. Harmless while it is always
  invoked with `-SkipPull`; would fail standalone under the scheduler account.

### Naming: two corrections, in order

**OpenCode Workbench -> Provenance** was wrong. It named the METHOD (evidence
provenance) rather than the subject, and had no connection to reverse
engineering, game security or kernel research.

**Provenance -> Ashline.** An "attack path" is what all of that content
actually traces: anti-cheat, malware, drivers, game internals. Short,
recognisable, and it sounds like tooling rather than documentation.

Both renames had the same trap. "workbench" and "provenance" are both ordinary
English words in this repository where they are exactly right and must not be
touched:

    "offline sessions, and lab benches are in scope"      a real lab bench
    "Signature and version provenance are"                driver provenance
    "Provenance lives outside the data"                   feed provenance
    "Mark every offset with its provenance"               offset provenance
    "ships binaries without source or provenance"         supply chain

So neither rename was a blind replace. Each phase replaced only exact tokens
and PRINTED every surviving occurrence with context for judgement, and the
survivors are 28 instances of the English word, verified one by one.

Also fixed a bug the first rename introduced: replacing the token
"opencode-workbench" globally had rewritten the generator scripts' output
paths to a directory that did not exist. The physical folder is now renamed to
D:\opencode\ashline, so those paths are true again - verified with Test-Path,
not assumed.

The physical directory is renamed; the GitHub repository still carries the old
name until it is renamed in the web UI.
