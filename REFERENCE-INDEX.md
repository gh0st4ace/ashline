# REA РІР‚вЂќ reverse engineering MCP

`rea` is a registered MCP server exposing ~170 tools. Load the
`reverse-engineer-anything` skill before using it.

Reach for REA when a claim depends on a shipped artifact rather than on source:
decompiling a binary or managed assembly, explaining how a feature works inside
an installed application, comparing versions, analyzing firmware, APK, Flutter
or Electron app, wasm, EVM bytecode, SQLite, PCAP, or capturing runtime
evidence from a process or browser.

Do not use REA for ordinary source-repository architecture work РІР‚вЂќ normal repo
tools are faster and sufficient there.

Engines installed: **Ghidra 12.1.4** (headless, default) and **IDA Pro 9.4**
(attached). Both verified working with real decompilation. Hopper is macOS/Linux
only and cannot be used here. Without an engine these still work: static
JavaScript analysis, managed code, SQLite, wasm, EVM bytecode, PCAP, signals,
evidence records.

Check readiness before promising an engine-backed result:

```powershell
rea-agents doctor
```

**IDA Pro provider (verified working).** IDA Professional 9.4 lives at
`D:\Programs\IDA Professional 9.4`. REA drives it through the `ida-pro-mcp`
1.4.0 bridge in `attached` mode, which requires a live IDA GUI with the MCP
plugin started. One command does all of it: it opens the binary, sends the
plugin hotkey, and waits for the RPC port.

```powershell
& "$env:USERPROFILE\.config\opencode\start-ida-mcp.ps1" <path\to\binary>
rea decompile <path\to\binary> 0x140001300 --provider ida --format json
```

Pass an **address**, not a bare function name. A bare name resolves for some
REA tools and fails others with `unreadable_output`; an address always
resolves.

Environment is persisted at User scope: `REA_IDA_MCP_CONFIG`, `REA_IDA_INSTALL`,
`GHIDRA_INSTALL_DIR`, `JAVA_HOME`.

Choose the provider deliberately:

| Need | Provider |
| ---- | -------- |
| Default, no setup, full capability | `ghidra` - headless, no GUI, no manual step |
| Second opinion, IDA's view, or an `.i64` already open | `ida` - run the launcher first |

`REA_ANALYSIS_PROVIDER=ghidra` is persisted so auto-selection always resolves.
Without it REA refuses to choose at all and reports `Multiple analysis providers
support this target`, because it counts a provider as available by
registration rather than by a live bridge. Do not auto-start the IDA GUI to
answer a question - nobody asked for a window on their desktop. Use ghidra
unless the task is specifically about an IDA database or a second opinion.

`hopper` cannot be used: it is macOS/Linux only and has no Windows build.

The skill's other three entries РІР‚вЂќ `rea-tool-design`, `rea-ci-tests-audit`,
`rea-changelog-update` РІР‚вЂќ are for developing REA itself, not for analysis. Their
relative links into `docs/` do not resolve from the install path.
